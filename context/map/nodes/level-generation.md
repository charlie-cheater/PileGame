# 节点:关卡生成算法(仿真玩家代理 × 渐进式规划器)
> 状态:🟡 求解器①②③④已实现并迭代(③决策扫描梯 v1,2026-11-23;匹配消耗改为消除模拟 + 拾取差分择优,2026-11-24);③决策逐梯改造中(第一阶梯 slot-close 已完成);需更多资源的 match 三梯待做;⑤预期对账与规划器未动工
> 确认:2026-11-21(来源:用户会话指示);结构细化 2026-11-22~24

## 内容(已确认)

**定位:设计性系统,非验证性求解器。** 传统求解器(最短时间找解 / 解数评难度、依赖完整关卡数据)被明确否定为目标;本系统为**尽可能符合人类行为模式的仿真玩家代理**,与**渐进式关卡规划器**构成闭环:

- **代理四要素**:参数集(人格档位)、内部状态、评估行为、操作行为
- **基于有限的、不完整的关卡进行操作**:给出可能的操作 + 操作后的游戏状态变化 + 对难易度的感知
- **反馈闭环**:上述数据作为关卡规划器的输入,渐进式评估并生成关卡后续内容

**求解器执行循环(2026-11-22 定稿,已实现①~④):**
①感知 → ②分析 → ③决策 → ④操作 →(⑤预期:前向模型已由决策产出的 forecast 承载,对账/惊讶度未实现)→ 回①;迭代单位 = 1 次拾取及其结算;出口 = 清空/槽满判负

**求解器设计结构(已实现,2026-11-23):**
- **感知边界**:感知集 = 有可见像素的 pile 牌(exposedArea > 0)+ 槽内牌;身份识别阈值 0.25(占位,两段式待定);未识别牌拷贝遮蔽 elementId;主观视图复用 Tile/TileDerived(拷贝 + 子集重算),隐藏牌对代理不存在
- **v3 等价定理背书**:感知子集重算的覆盖并集 = 真实并集 ⇒ 主观可点性精确等于真值(不确定只残留在身份与隐藏节点存在/揭示)
- **分析算子**(2026-11-23 设计者审阅后收敛:对外仅 `analyze()` 一个入口,各报告为 `AnalysisResult` 子属性 reveal / groups / matches;分析只接收主观视图,与真值的对账归 Runner 驱动侧与 tests):遮挡边/自建深度/揭露闭包(传递闭包大小)/可点性;同类归组(已识别牌按元素分组);揭露效能(独占遮挡口径:至少一像素仅由它覆盖,与移除语义精确对应;v1.6 起含**独占面积数据**——pair 分布保留 + 合计标量,消费端决定聚合/加权);**匹配消耗 v4 = 消除模拟的净占用峰值**(2026-11-24 设计裁定,见下)
- **匹配消耗 = 消除模拟的净占用峰值**(2026-11-24):对挖掘区(闭包(launcher) ∪ 闭包(target))做一次消除模拟,记录**额外槽位占用的峰值**。matchCost 单位 = 槽位格数,可与空槽数直接比较;`executable` 即 `峰值 ≤ 空槽数`。模拟规则:
  - 空槽视为无限——不因槽满中断,挖掘区内可合并的配对最终一定合并
  - 每步四阶段:牌入槽占位 → 统计占用(**峰值在此读取**)→ 检查匹配并消除 → 重新统计
  - 净占用 = 槽内总数 − 模拟开始时已有的槽内牌数;原有牌被用于配对时净占用随之下降(槽内已持伴、闭包仅 1 张时,额外占用 = 1——至少要 1 个空槽才能消掉已放入槽中的牌)
  - 从闭包外找伴**只找槽内的或当前可直接点击的**,不找被遮盖的——递归深度会超出一般人类的感知范围
  - 模拟结束时剩余的牌额外记录(`residual`:伴被压或身份未知而出不去的牌)
  - 挖 launcher / target 时只拿各自闭包内的成员(实现时补的规则:否则挖 target 会顺手拿走 launcher 的遮挡者)
  - 启动牌 = 配对两张中获取成本最低者;获取成本(`flatCostOf`:槽内 0 / 可点 1 / 被压 1 + 闭包大小)**仅用于候选排序,不是消耗**
  - **候选规则的推论**:挖掘区内那张同元素牌压着某候选时,它必不比被压者贵,会被选为 target(「中间的那张会被选为 target」,2026-11-24 设计者确认;穷举 57699 组几何核实)
  - 共同路径只计一次、可合并项的消化、+1 还是 +2,都不是显式规则,是模拟的自然结果
- **⛔ 已推翻的匹配消耗口径**(保留演进痕迹,均被 v4 取代):v2.2 获取成本 = 1 + (闭包+深度)/2 双口径平均;v2.3 递归定价(遮挡者成本递归;实测 dig 均值 9→86 分化过剧而回退,引擎已于 2026-11-24 移除);v3「闭包并集 − 严格可合并项 + 加项」公式(2026-11-24 设计者裁定:加多少项、剔多少对都是在近似一个本可直接算出的量)
- **决策 v1 = 扫描梯瀑布**(`Ladder.ts`,2026-11-23 定稿):决策以「扫描梯」模式围绕分析数据思考——梯为有序、可插拔的数组,依序过梯、首个非空胜出、全空走内置兜底;每梯产出 **AgentOperation = 移除动作 + 原因 + 预期**(结构化:rule / utility / runnerUp / chain;预期 = pairCompletes / slotAfter / exposes / confidence / forecast),预期即⑤阶段的对账面;Runner 增 v2 决策轨,随机 / 见对先拿策略保留为对照基线
- **梯序(休闲基线)**:slot-close(闭合槽内半张)→ pair-complete(双亮对,P2 折叠)→ chain(借槽两步闭合)→ wander(无信号随机)。slot-close 先于 pair-complete 为裁定项:设计稿原序经平盘推演证伪(连续持半致槽满);cheap-hold / dig / forced 待实现
- **拾取差分 = 梯内择优的统一依据**(2026-11-24 设计定论):无论决策阶段做何种选择,最终只产生**一个动作——拾取且仅拾取一张牌**。故可预演这个拾取动作得到新盘面,对新盘面重新执行分析,比较前后分析数据的差异;找到合适的量化方法即可评估拾取动作的收益,并用它对候选排序。现状:
  - **三个分量**:**新增可执行匹配数**(原来做不了、现在能做了)/ **类型升级数**(同一配对 (launcher, target) 的可达性上升 dig→hold→double→close,外加新出现的 close / double 型)/ **峰值下降总量**(保留匹配的 matchCost 正向差值之和)
  - **排序 = 字典序**:新增可执行 > 类型升级 > 峰值下降总量;平分取 tileId 小者。**不是加权和**。权重裁定:**新增可执行匹配权重最大**——更符合真实人类玩家的直觉;类型升级次之;**只有带不出 close / double 型时才更关注总量下降**。**进槽成本不计**——同梯内所有操作的进槽成本统一
  - **预演只在当前感知集上进行**:新露出的牌不进预演,操作落定后由下一轮 ①感知 → ②分析 纳入(故预演收益是真实收益的下界)
  - **槽内状态变化纳入预演**:拾取导致闭对则两张离场,后续匹配的可执行性按**合并后的资源余量**判定
  - **状态恢复**:预演在视图拷贝上做,不修改原主观视图与真实 Board,无需恢复
  - **已接入的梯**:仅 `slot-close`(其候选来源同时改为 MatchReport 的 close 型匹配,行为边界不变——只处理立即可闭合的,槽内持伴但伴被压属 hold 型不收);`pair-complete` / `chain` 待逐梯改造
  - **编辑器盘开局**(5 张可点):拿 dot5(L2)→ 新增可执行 1 / 升级 0 / 峰值降 15;拿顶层 wan5 → 0 / 3 / 11;拿 dot6 → 0 / 0 / 3;拿 wan8、dot8 → 0 / 0 / 1——三级逐级分出先后
- **梯内平级择优 = 揭示预演**(`simulateReveal`,主观前向模型,深度 1)—— 🟡 *2026-11-24 起 slot-close 已改用拾取差分;pair-complete / chain 仍用本口径*:假想移除候选,其**直接覆盖**的目标二分——预演后变可点者按激活计值(closes 1.0 / pairs 0.8 / lone 0.2),仍被压者记 near(剩余遮挡者里有可点牌)/ far;效能 = 0.7 × Σ激活 + 0.3 × near 张数,**求和不归一**(揭 3 张优势牌好过 2 张;布局规则下单次揭露 ≤ 4 张);平分取 tileId 小者。预演对可点性是乐观估计(隐藏牌不在感知集)——即⑤惊讶度的来源;hiddenRisk 字段预留、暂恒 0(设计者另有计划)。其产出仍用于各梯的 `expectation.forecast`(⑤对账面)与 chain 梯的链路判定
- **chain 梯(借槽两步闭合)**:拿一张可点牌,它揭出的牌下一步拿走即可闭对;两类同梯、按效能择优——slot(与槽内已有半张闭合)/ pair(与本次拿的这张闭合);可用性是开关而非打分项:空槽 < 2 整梯让位(按当前容量计,槽位扩充道具下自动适应);pair 加分 0.3(裁定「槽位干净更重要」)。更深的链(深度 3)暂不做
- **语料**:RandomFill(骨架 → FULL 随机配对,seed 确定);测试/编辑器盘面统一 test_layout.json + seed 7
- **debug 验收**:编辑器选中交互(点牌显示两行信息:揭露效能行 + 匹配消耗行【匹配类型 / 搭档 / 消耗 N/空槽数 格 / 逐步占用序列 / 剩余牌】;高亮:选中 / 直接遮挡 / 挖掘区成员 / 匹配搭档 / 模拟结束时卡在槽里的剩余牌)
- **编辑器盘实测**(test_layout + seed 7,空槽 4):11 个匹配的峰值 3~9(均值 7.18),**仅 1 个可执行**(dot5,3 格);每个匹配模拟后剩 1~6 张,基本都含顶层那张牌(其伴埋在最底层)——执行任何匹配后槽里都会留下等不到伴的牌

**配对形态(现阶段锁定):全图匹配(FULL + FULL)**
- 同元素牌完全可互换,不存在"指定的另一半";可解性只取决于元素→位置分配
- 二分对(L/R)延后:`tile.ts` 数据契约(variant/canPair)已支持,启用无需改逻辑
- **元素重复度(每元素 2/4/6 张)成为内容设计主轴**:批量实证(2026-11-23,test_layout 盘,7×5 + 见对先拿通关率 29% vs 35×1 纯随机 0%)

**已推导的结构性质(实现基础,见 background)**
- P1 单调性:移除只增可点集 → 已可点牌永远可点
- P2 双亮对折叠:两张可点的同元素牌立即成对移除永不变坏(人类同样"见对先拿")
- P3 状态归约:模拟/搜索状态 = 已移除集;槽内容可从中导出,容量约束 = 开对 ≤ 3

**混合架构分工**:正确性(必可解)由构造保证(逆向/增量放置 + P1/P2);代理负责体验评估;验证性搜索降级为终检安全网。

**难度观**:难度 = 代理与内容交互的**体验轨迹**(张力曲线、峰值槽压、被迫感、犹豫度),非关卡内禀标量;目标映射情绪锚点(慢节奏、失败温柔),非最大化难度。
