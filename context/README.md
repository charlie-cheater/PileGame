# AI Context Base (context/)

本目录是 PileDisassembleGame 的 **AI 协作上下文库**,与 `assets/` 平级,**不参与** Cocos Creator 资产导入与构建。

## 组织结构:三个核心分区

| 分区 | 概念 | 内容 | 性质 |
|---|---|---|---|
| [`history/`](history/) | **对话历史** | 用户的要求 + AI 操作的要点,按时间线 | 只增不改 |
| [`map/`](map/) | **认知地图** | **设计者确认保留**的概念、灵感、关系,以拓扑结构组织(`MAP.md` 总览 + `nodes/` 节点) | 随设计演进更新 |
| [`background/`](background/) | **背景知识** | 参考分析(原作概念图)、麻将优势解构、取材资源库、Cocos 工程事实 | 稳定积累 |

根文件与资源:

- `STATUS.md` — **会话入口**:当前阶段、待办、未决事项快照
- `assets/` — 概念图等图片资源

## 认知地图规则

- **节点 = 经设计者确认的方向**;节点内的具体参数可以未决(标 ⏳)
- **关系(边)= 概念间的约束/依赖/触发**,统一登记在 `MAP.md`
- **未确认的想法不进地图**:先记入 history,经确认后由 AI 提取为节点
- **推翻旧概念**:节点标记 ⛔ 并注明取代者,不删除(保留演进痕迹)

## AI 会话协议

**进入会话(建立背景):**
1. 读 `STATUS.md` —— 当前阶段与待办
2. 读 `map/MAP.md` —— 设计现状(确认了什么、概念间关系)
3. 按任务需要深入节点或 `background/`

**离开会话(持久化)——仅在用户明确发起时执行(2026-11-18 起):**
- **归档写入一律由用户主动发起**:用户说"归档 / 记录一下 / 更新状态"等指令后,AI 才执行对应分区写入(STATUS / history / map / background)
- AI **不自动归档**;可在合适时机用一句话**建议**归档,但不代替执行
- 大部分日常讨论不归档,只归档用户点名的决策、知识与进展

## 写作原则

- 正文中文;代码标识符、路径、API 名保持原文
- 文件名小写 kebab-case;日期 `YYYY-MM-DD`
- `STATUS.md` 是唯一入口,必须反映真实状态
- 背景知识只存"代码/资源里看不出来的"信息
